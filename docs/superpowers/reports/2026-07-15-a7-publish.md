## VPS Prerequisites

Install the Protomaps `pmtiles` CLI before running `publish`. A7 is pinned to
`go-pmtiles` `v1.31.1` from
<https://github.com/protomaps/go-pmtiles/releases/tag/v1.31.1>. The CLI is a
single binary and A7 fails fast before any staging work if it is not on `PATH`
or `pmtiles version` does not report `1.31.1`.

No-sudo Linux x86_64 install:

```bash
mkdir -p "$HOME/.local/bin" /tmp/making-tracks-tools
curl -fL \
  https://github.com/protomaps/go-pmtiles/releases/download/v1.31.1/go-pmtiles_1.31.1_Linux_x86_64.tar.gz \
  -o /tmp/making-tracks-tools/go-pmtiles_1.31.1_Linux_x86_64.tar.gz
echo '71b2212d6796e172b8ba27c21e662c25ec93cacdb88adc35e508617e720f6292  /tmp/making-tracks-tools/go-pmtiles_1.31.1_Linux_x86_64.tar.gz' \
  | sha256sum -c -
tar -xzf /tmp/making-tracks-tools/go-pmtiles_1.31.1_Linux_x86_64.tar.gz \
  -C "$HOME/.local/bin" \
  pmtiles
chmod +x "$HOME/.local/bin/pmtiles"
export PATH="$HOME/.local/bin:$PATH"
pmtiles version
```

Expected source and size:

- `contracts/regions/malaysia.json` configures `source_pmtiles` as
  `https://build.protomaps.com/20260714.pmtiles`.
- `cut_basemap` cuts from that configured source into `malaysia.pmtiles` using
  `pmtiles extract INPUT OUTPUT --maxzoom=14 --bbox=99.64,0.85,119.27,7.36`.
- The configured measured Malaysia z14 archive size is `223,155,574` bytes.
  A7 now rejects extracted basemaps whose byte size differs from that exact
  measurement, then records the final basemap SHA-256 in `manifest.json`.
  Reserve at least 1 GiB of free staging space because the publish build keeps a
  work copy and final staged copy during assembly.
- A local planet/source archive is not required for A7 acceptance: the
  Protomaps CLI supports remote HTTPS PMTiles inputs for `extract`, and the A0
  region-config schema requires an HTTPS `source_pmtiles`. Basemap generation is
  required for acceptance because the A7 manifest contract includes the
  `basemap` object; places-tiles-only output is not a valid A7 publish artifact.

Manual basemap source smoke command, matching the publish config:

```bash
pmtiles extract \
  https://build.protomaps.com/20260714.pmtiles \
  /data/mt-data/a7-staging/malaysia-smoke.pmtiles \
  --maxzoom=14 \
  --bbox=99.64,0.85,119.27,7.36
```

## Registry Location

`pipeline/config/reconcile.json` keeps the portable relative paths
`registry/{region}.jsonl` and `reconcile-review/{region}.jsonl`, but runtime now
resolves those relative paths beside the SQLite working DB, not the operator's
current directory. With the real-run DB path below, publish reads:

- Registry: `/data/mt-data/malaysia/registry/malaysia.jsonl`

The reconcile stage also writes its review artifact beside the DB:
`/data/mt-data/malaysia/reconcile-review/malaysia.jsonl`.

This matches the working store boundary: a retained `/data/mt-data/malaysia`
directory carries the DB plus its private ID-registry state, independent of
which checkout/worktree is used to launch the command.

## Local Staging Command

Run on the VPS against the retained real Malaysia store:

```bash
cd pipeline
uv run --extra dev mt-pipeline \
  --region malaysia \
  publish \
  --db /data/mt-data/malaysia/work.db \
  --run-id real-malaysia-20260715 \
  --publish-version 20260716T000000Z \
  --generated-at 2026-07-16T00:00:00Z \
  --scoring-config-version scoring-v1 \
  --staging-dir /data/mt-data/a7-staging
```

Expected output:

- Local staging tree at `/data/mt-data/a7-staging/malaysia/20260716T000000Z`.
- `manifest.json` written after tile and basemap artifacts.
- `current.json` is not written locally by `build_staging`; it is part of the R2 publish plan and flips only after manifest upload.
- Counts to paste here after the VPS run: tile total, total published, by-tier counts, `uncategorized_excluded`, `invalid_excluded`, `non_winner_excluded`, `overflow_dropped`, basemap bytes.

## R2 Upload Gate

R2 upload is not run from this workstation. It requires Rob's scoped R2 credentials via one `op run` invocation and operator verification of the local staging output first.

```bash
op run --env-file=../.env.tpl -- uv run --extra dev mt-pipeline \
  --region malaysia \
  publish \
  --db /data/mt-data/malaysia/work.db \
  --run-id real-malaysia-20260715 \
  --publish-version 20260716T000000Z \
  --generated-at 2026-07-16T00:00:00Z \
  --scoring-config-version scoring-v1 \
  --staging-dir /data/mt-data/a7-staging \
  --upload
```

Upload verification checklist:

- Public bucket receives `malaysia/20260716T000000Z/tiles/...`, `malaysia/20260716T000000Z/malaysia.pmtiles`, and `malaysia/20260716T000000Z/manifest.json`.
- Public `malaysia/current.json` flips only after the manifest op.
- Private registry remains in `making-tracks-state`; no registry/cache/feedback op targets `making-tracks-tiles`.
- Rollback is a repoint of `malaysia/current.json` to the prior publish version.
